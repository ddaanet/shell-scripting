# inbox

Where a session working in another repository drops a brief, note or finding
that concerns shell-gotchas — typically a shell pitfall observed there that the
skills should catalog.

Drop the file here, not at the repo root. A brief at the root is easy to
mistake for a tracked project document.

`plans/` is for this repo's own prospective work — plans, specs, briefs a
shell-gotchas session wrote for itself. `inbox/` is for what arrives from
outside. Triaging an inbox file usually means landing its content in a skill
and deleting it, declining it with the reason recorded, or promoting it into
`plans/` if it becomes work this repo will schedule.

Git does not track empty directories, which is why this file exists.
